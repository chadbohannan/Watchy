# Serial Upload Timeout: "Failed to connect to ESP32"

A user-facing firmware flash failure where `esptool` could not establish a serial connection with the ESP32, reported in [GitHub issue #147](https://github.com/sqfmi/Watchy/issues/147) (open as of 2026-08). It is not a firmware bug in this repo — the flash tooling never reached the ROM bootloader — but it is the most-commented Watchy issue (38 comments) and the first stop for anyone struggling to upload a sketch.

The failure presented as `A fatal error occurred: Failed to connect to ESP32: Timed out waiting for packet header` after `esptool` printed repeated `Connecting........_____....._` progress dots. The user had uploaded successfully before and had not changed wiring; the unit visibly restarted as if the reset pin were being stroked. The report listed a full toolchain inventory (Arduino IDE 1.8.19, `esptool v3.1`, ESP32 core 2.0.2, Watchy 1.3.3, GxEPD2 1.4.5) and confirmed that NTP/weather, the vibration motor, and the accelerometer all still worked — i.e. the board and firmware were healthy; only the flash path failed.

Common causes for this class of failure include a charge-only (not data) USB cable, a driver/serial-enumeration issue, a stale bootloader state, or holding the board outside the documented [bootloader mode](../runbooks/flashing-serial.md) entry sequence. Because the device still runs, the fix is environmental/toolchain, not a reflash of the application: re-enter bootloader mode (hold Back & Up >4 s, release **Back first** per the [getting-started source](../../sources/2026-08-14-getting-started.md)), switch to a data cable, and re-select the serial port.
