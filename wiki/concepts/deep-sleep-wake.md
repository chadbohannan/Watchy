# Deep Sleep & Wake Model

The entire Watchy runtime is built around deep sleep. There is no event loop: `Watchy::deepSleep()` (`Watchy.cpp:98`) is always the last call in `init()`, and every wake source maps to a suspend/resume cycle that redraws and returns to sleep. This model is what makes the watch's months-long battery life possible and is analyzed in the [Power Budget Analysis](../syntheses/power-budget.md). *Verified against the repo at `d1d233c` as of 2026-08.*

**Wake sources.** `deepSleep()` arms different combos per board:
- **Timer / RTC alarm** — the once-per-minute tick. On V3 this is `ESP_SLEEP_WAKEUP_TIMER` (a timer wakeup sized to the next minute boundary, computed via `rtc_clk_32k_enable` and `getLocalTime`, `Watchy.cpp:112`). On V1/V2 it is `ESP_SLEEP_WAKEUP_EXT0` on `RTC_INT_PIN` from the external [RTC](../components/rtc.md)'s alarm.
- **Buttons** — `ESP_SLEEP_WAKEUP_EXT1` on `BTN_PIN_MASK` (`ANY_HIGH` on V1/V2, `ANY_LOW` on V3 given the pulls), waking on any of the four buttons or the accelerometer interrupt ([BMA423 Accelerometer](../components/bma423-accelerometer.md)).
- **USB** — on V3, `ESP_SLEEP_WAKEUP_EXT0` on `USB_DET_PIN` reacts to USB plug/unplug, and the resulting state is persisted in the `USB_PLUGGED_IN` [RTC_DATA_ATTR](../concepts/rtc-data-attr.md) flag.

**Wake handling in `init()`** (`Watchy.cpp:39`): after initializing I2C, the [RTC](../components/rtc.md), and the [Display](../components/display.md), a `switch` on `esp_sleep_get_wakeup_cause()` routes each wake. The timer/EXT0 alarm branch calls `showWatchFace(true)` for a partial-refresh clock tick (and optionally a vibration on the hour through `vibrateOClock`), or returns the menu to the watchface if it has lingered too long (`guiState`/`alreadyInMenu`). The button wake calls `handleButtonPress()`. USB wake redraws and updates `USB_PLUGGED_IN`. The `default` (reset) case reconfigures the RTC with an optional datetime, (re)runs `_bmaConfig()`, reads boot time, does a full-refresh draw, vibrates, and disables all wake sources to start clean.

**Button debounce/long-press.** All input is handled inside `handleButtonPress()` (`Watchy.cpp:135`), which decodes the ext1 wakeup bit against the button masks. This includes the **fast menu**: a 5-second window (`lastTimeout`/`millis()`) in which button state is polled with `digitalRead` to allow rapid repeated presses without cycling deep sleep, before the watch gives up and goes back to sleep.

**Cooldown then sleep.** Every wake path — including `handleButtonPress` at its end — falls through to `deepSleep()`, which hibernates the display (`display.hibernate()`), clears the RTC alarm, configures the next wake sources, and calls `esp_deep_sleep_start()`. On V1/V2 it also sets every GPIO to input to stop current leak, with a fixed bitmask of GPIOs ignored to avoid reset. Because state is carried by [RTC_DATA_ATTR](../concepts/rtc-data-attr.md), each wake resumes exactly where the previous one left off.
