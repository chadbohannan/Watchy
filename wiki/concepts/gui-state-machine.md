# GUI State Machine

Watchy's interface is a small, integer-driven state machine whose state survives deep sleep in `guiState` ([RTC_DATA_ATTR](../concepts/rtc-data-attr.md)). The states are defined in [Board & Config](../components/board-config.md): `WATCHFACE_STATE -1`, `MAIN_MENU_STATE 0`, `APP_STATE 1`, and `FW_UPDATE_STATE 2`. Transitions are driven entirely by button wakes routed through `handleButtonPress()` (`Watchy.cpp:135`), which runs in the [deep sleep & wake model](../concepts/deep-sleep-wake.md). *Verified against the repo at `d1d233c` as of 2026-08.*

**The watch face (default state).** In `WATCHFACE_STATE`, button wakes that match the Menu button call `showMenu()` and move to `MAIN_MENU_STATE`; Up/Down are ignored (they're reserved for the menu), and Back does nothing. The per-minute tick keeps the face drawn in this state via partial refresh.

**The menu.** `showMenu()` (`Watchy.cpp:289`) and the near-identical `showFastMenu()` (`Watchy.cpp:322`) render the six items — About Watchy, Vibrate Motor, Show Accelerometer, Set Time, Setup WiFi, and Sync NTP — with the currently selected index highlighted by a white rectangle. `HandleButtonPress` interprets:
- **Menu:** select the highlighted item (switch on `menuIndex` 0–5 → `showAbout`, `showBuzz`, `showAccelerometer`, `setTime`, `setupWifi`, `showSyncNTP`) while in `MAIN_MENU_STATE`; or enter the menu when on the watchface. Selecting an app moves into `APP_STATE`.
- **Back:** from the menu, return to the watchface; from an app (`APP_STATE`) or update state, return to the menu.
- **Up/Down:** cycle `menuIndex` (wrapping at `MENU_LENGTH-1`) and redraw with a partial refresh.

The same selection logic is duplicated in the fast-menu polling loop so a held/repeated Menu press works within the 5-second debounce window.

**App states.** The apps — About, vibrate, accelerometer, set-time, WiFi setup, and NTP sync — each set `guiState = APP_STATE` and draw their screen, and Back returns to the menu. **About** (`showAbout`, `Watchy.cpp:354`) is read-only: it reports `WATCHY_LIB_VER`, `getBoardRevision()`, `getBatteryVoltage()`, uptime (legacy boards only), and the persisted SSID/IP. **Vibrate** (`showBuzz`) just buzzes and returns. **Set Time** (`setTime`, `Watchy.cpp:425`) is a self-contained modal: it reads the RTC into local hour/minute/day/month/year, then enters an *awake* loop (no deep sleep) stepping a `setIndex` cursor (`SET_HOUR`→`SET_DAY` from `config.h`) with Menu/Back, and incrementing/decrementing the selected sub-field with Down/Up, wrapping at each field's max. The active field blinks (a `blink` toggle, white↔black text) in the 7-segment time display with partial refresh. On exit (setIndex past `SET_DAY`) it writes the values back via `RTC.set(tm)` and returns to the menu. **Show Accelerometer** (`Watchy.cpp:593`) similarly holds the CPU awake in a 200 ms poll loop reading the [BMA423](../components/bma423-accelerometer.md) until Back is pressed. WiFi setup and NTP sync hand off to [WiFi & NTP](../components/wifi-ntp.md). FW update interacts with [BLE OTA](../components/ble-ota.md). Because About/Vibrate directly call `getBatteryVoltage()`/`vibMotor()`, these expect `guiState = APP_STATE` is enforced by `handleButtonPress` before dispatch.

**Auto-return.** A guard in the timer-wake branch prevents the menu from lingering indefinitely: the `alreadyInMenu` [RTC_DATA_ATTR](../concepts/rtc-data-attr.md) flag makes the first subsequent minute tick return `guiState` to `WATCHFACE_STATE` and redraw the face, so an idle watch never burns battery on a stale menu.
