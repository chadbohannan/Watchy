# RTC

Watchy keeps time with a real-time clock that is the primary wake source for the once-per-minute draw tick. The RTC abstraction in `src/WatchyRTC.h` supports two external chips — the DS3231 (`DS3232RTC` class, address `RTC_DS_ADDR` 0x68) and the PCF8563 (`Rtc_Pcf8563`, address `RTC_PCF_ADDR` 0x51) — but an alternative implementation entirely replaces this on V3 hardware. *Verified against the repo at `d1d233c` as of 2026-08.* When time goes wrong, the fault signature can point at this component — see the [garbled RTC time incident](../incidents/2023-10-01-rtc-time-garbled.md).

`WatchyRTC::init()` (`WatchyRTC.cpp:5`) *probes* the I2C bus at runtime rather than trusting compile-time pins: it first attempts a bus transaction to the DS3231 address (`0x68`) and, if that ACKs, selects the DS3231; otherwise it probes the PCF8563 address (`0x51`). This means the board wiring determines the chip actually used, though in practice it aligns with `rtcType`. The public surface is uniform — `init()`, `config(datetime)`, `clearAlarm()`, `read(tmElements_t&)`, `set(tmElements_t)`, and `temperature()` — so callers in [Watchy Firmware](../systems/watchy-firmware.md) never care which chip is present.

The once-per-minute alarm, which drives the [deep sleep & wake model](../concepts/deep-sleep-wake.md), is set during configuration. For the DS3231, `_DSConfig()` (`WatchyRTC.cpp:90`) writes the time, disables the square-wave output, then arms `ALM2_EVERY_MINUTE` with `alarmInterrupt(ALARM_2, true)`. For the PCF8563, `_PCFConfig()` (`WatchyRTC.cpp:111`) writes the date/time and calls `clearAlarm()`, which (`WatchyRTC.cpp:32`) clears the alarm flag and re-arms the alarm for exactly one minute in the future. `clearAlarm()` is also called at the top of every `deepSleep()` to rearm the minute tick after each wake.

Weekday handling differs between the two libraries: the DS3231/TimeLib world uses a 1–7 range, while the PCF8563 stores 0–6. `read()` and `set()`/`_PCFConfig()` normalize this in both directions (`tm.Wday = rtc_pcf.getWeekday() + 1`, and `tm.Wday - 1` when writing), and `set()`/`_PCFConfig()` recompute the weekday via `makeTime`/`breakTime` before storing it. `temperature()` returns the DS3231's built-in temperature in Celsius, or 255 on the PCF8563 (which has no temperature sensor).

For the ESP32-S3 V3 board, `Watchy32KRTC` (`src/Watchy32KRTC.h`) is used instead. It has no external chip and no I2C: `init()` and `clearAlarm()` are empty, and `config`/`read`/`set` drive the ESP32's system clock directly. `config()` parses the `YYYY:MM:DD:HH:MM:SS` string with `strptime` and calls `settimeofday`; `read()`/`set()` convert between `tmElements_t` and `struct tm`/`timeval`. There is intentionally no set-time PID loop — the system clock IS the source of truth. `temperature()` always returns 0. Time on V3 is additionally bridged to the RTC-alarm cadence in `deepSleep()` (`Watchy.cpp:112`), where `rtc_clk_32k_enable(true)` and a timer wakeup are set so `getLocalTime` remains usable for computing seconds-to-next-minute.

For the non-V3 boards, DateTime strings are split with the `_getValue(data, ':', index)` helper (`WatchyRTC.cpp:137`), which parses a colon-delimited field without `String` dependency. Year handling uses TimeLib's `CalendarYrToTm` (subtract 1970) on entry and `YEAR_OFFSET_DS`/`YEAR_OFFSET_PCF` on exit, so callers always work with calendar years at the `Watchy` layer.
