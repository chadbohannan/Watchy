# Board & Config

Board-specific pin assignments, compile-time tweaks, and the settings blob all live in `src/config.h`. This is the single source of truth for hardware variation across the V1/V1.5/V2 and V3 boards, and it is included broadly across the [Watchy Firmware](../systems/watchy-firmware.md). *Verified against the repo at `d1d233c` as of 2026-08.*

**Hardware selection.** Watchy spans two CPU families. The **V3** board is an **ESP32-S3**, selected by `ARDUINO_ESP32S3_DEV` — this is the board the official getting-started guide targets ("ESP32S3 Dev Module", 8M with spiffs). The older **V1.0 / V1.5 / V2.0** boards use the **classic ESP32** (ESP32-PICO-D4, Xtensa LX6) and share the `#else` branch. Everything in that branch requires one of `ARDUINO_WATCHY_V10`, `ARDUINO_WATCHY_V15`, or `ARDUINO_WATCHY_V20` to be defined at the project level; if none is, the header emits `#pragma message` warnings and defaults to `ARDUINO_WATCHY_V20`. Because of that default, and because esptool reads the live chip during upload, a non-V3 Watchy — the currently widely-sold classic board — is an ordinary (non-S3) ESP32; building for the S3 FQBN from the docs is rejected with a chip mismatch (see the [wrong-chip upload rejection incident](../incidents/2026-08-14-wrong-chip-upload-reject.md)). The board revision is what picks the [RTC](../components/rtc.md) type and, at runtime, is detected by `getBoardRevision()` (`Watchy.cpp:769`).

**V3 pins** (SDA 12, SCL 11, SPI on SS 33 / MOSI 48 / MISO 46 / SCK 47, buttons MENU 7 / BACK 6 / UP 0 / DOWN 8, accel ints 14/13, vib motor 17, battery ADC 9, charge status 10, USB detect 21). The legacy boards share MENU 26 / BACK 25 / DOWN 4 / display CS 5 / RES 9 / DC 10 / BUSY 19 / ACC_INT_1 14 / VIB 13, but differ on UP and the battery ADC: V1.0 uses UP 32 / ADC 33, V1.5 UP 32 / ADC 35, V2.0 UP 35 / ADC 34, with `RTC_TYPE` 1 (DS3231) on V1.0 and 2 (PCF8563) on V1.5/V2.0.

**Wake masks.** `MENU_BTN_MASK`, `BACK_BTN_MASK`, `UP_BTN_MASK`, `DOWN_BTN_MASK`, and `ACC_INT_MASK` are `BIT64(pin)` constants combined into `BTN_PIN_MASK`, which the [deep sleep & wake model](../concepts/deep-sleep-wake.md) uses to arm the ext1 wakeup on button and accelerometer pins.

**Display geometry.** `DISPLAY_WIDTH`/`DISPLAY_HEIGHT` are 200×200. The panel itself is documented in the [Display](../components/display.md) page.

**Firmware constants.** `WATCHFACE_STATE -1`, `MAIN_MENU_STATE 0`, `APP_STATE 1`, `FW_UPDATE_STATE 2` drive the [GUI state machine](../concepts/gui-state-machine.md); `MENU_HEIGHT 25` / `MENU_LENGTH 5` lay out the five menu items; the editor fields `SET_HOUR`…`SET_DAY` and `HOUR_12_24` drive `_editDateTime()`, and the `SETTIME_NTP`…`SETTIME_DATE` row indices (`SETTIME_ROWS 5`) lay out the Set Time list in `setTime()`. BLE identity (`BLE_DEVICE_NAME "Watchy BLE OTA"`, `WATCHFACE_NAME`) and software/hardware version macros back the [BLE OTA](../components/ble-ota.md) service. `WIFI_AP_TIMEOUT 60` and `WIFI_AP_SSID "Watchy AP"` feed [WiFi & NTP](../components/wifi-ntp.md). `WATCHY_LIB_VER "1.4.14"` is the reported library version.

**Battery sensing.** `getBatteryVoltage()` (`Watchy.cpp:756`) reads `analogReadMilliVolts(BATT_ADC_PIN)`. On the legacy boards this is multiplied by 2.0 (the battery feeds a 1/2 divider, so the ADC alone reports half the cell voltage). On V3 the multiplier is instead `ADC_VOLTAGE_DIVIDER`, defined in `Watchy.h` as `(360.0f+100.0f)/360.0f` to correct the V3's divider network. The raw ADC pin per revision is listed above (`BATT_ADC_PIN` 33/35/34/9). This feeds the battery readouts in `showAbout()` and [watchfaces](../concepts/watchfaces.md).

**Settings struct.** The `watchySettings` and `weatherData` typedefs live in `src/Watchy.h`. `watchySettings` carries the weather fields (`cityID`, `lat`, `lon`, `weatherAPIKey`, `weatherURL`, `weatherUnit`, `weatherLang`, `weatherUpdateInterval`), NTP (`ntpServer`, `gmtOffset`), and `vibrateOClock`. It is passed to the `Watchy` constructor and copied into `Watchy::settings`. In the example faces the values originate from macros in each folder's `settings.h` (e.g. `CITY_ID`, `OPENWEATHERMAP_URL`, `TEMP_UNIT`) rather than being hardcoded in the library.
